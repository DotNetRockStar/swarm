    What is MCP?

    The Model Context Protocol (MCP) is an open standard that lets an AI assistant — Claude Desktop, Claude Code, or any other MCP-compatible client — talk directly to this server: search your library, look up an entry's details, check which swarm devices are online, and review recent client errors. It's read-only; the assistant can look, not touch — it can't change settings, trigger a rescan, or edit metadata.

    Try asking

    Once connected, just ask in plain language — no special syntax needed:

    Claude / Codex
    > What movies do I have from 2019 that I haven't watched yet?
    > Is my living room Fire TV online right now?
    > Find every comedy episode that's had a playback error recently.
    > Give me a one-line synopsis of every unwatched movie under 90 minutes.
    > Which of my liked albums haven't I played in a while?

    Server

    Takes effect on next restart of this app. Reachable from any device on your network — there's no login, so only enable this on a network you trust.

    The media server
    
    
    
      
    What this app does
    
      
    This is the SWARM server — it lives on the machine that actually holds your movies, shows, and music. It scans the media roots you point it at (see the Details tab), keeps a searchable library with artwork and metadata, and streams files directly to any client in your swarm over an encrypted connection. When a client can't natively decode a file, this server transcodes it on the fly to an adaptive HLS stream instead of failing to play.
    
    
    
    
    
      
    One library, every server
    
      
    If you run more than one SWARM server (say, one at home and one at a cabin), clients merge every reachable server's catalog into a single browsable library — the same file on two servers shows up once, with whichever source is actually reachable picked automatically at play time.
    
    
    

    
    The clients
    
    
    
      
    Fire TV, with more on the way
    
      
    The first SWARM client is a native Fire TV app (Kotlin, Compose for TV, built on Media3/ExoPlayer) — a full D-pad-driven 10-foot browsing experience for movies, shows, and music, plus Kid Mode parental controls. It's built to add sibling clients for other platforms over time; every client talks the same protocol this server does, so they all share one swarm and one library.
    
    
    

    
    Security & privacy
    
    
    
      
    The short version
    
      
    Your media never leaves your own devices. There's no cloud server storing your files, no upload step, and no company that could see what you watch or listen to. When you press play, your Fire TV (or other client) connects directly to your own server and streams the file straight from it — nothing in between ever has a copy.
    
    
    
    
    
      
    Direct, device-to-device streaming
    
      
    Every stream goes straight from your server to your client over a private connection — the same way two phone calls don't route through a switchboard operator anymore. No third-party server ever sits in the middle relaying, caching, or seeing the video/audio itself.
    
    
    
    
    
      
    What the STUN server actually does (and doesn't)
    
      
    Two devices behind separate home routers usually can't just dial each other directly — routers weren't built to accept an unsolicited connection. The STUN server's only job is introductions: it tells your two devices what address to reach each other at, the same way a switchboard used to just connect two lines and then get out of the way. Once that handshake finishes, your devices talk to each other directly — the STUN server is never in the path your media actually travels, and it has no way to see, log, or store any of it.
    
    
    
    
    
      
    Encryption and identity
    
      
    Every device-to-device connection is encrypted with TLS 1.3 — the same encryption standard used by online banking. It's also mutual: your server and your client each present a certificate and check the other's, so a device can't stream from your server (or accept a connection claiming to be it) unless it's genuinely one you've invited. An eavesdropper on the network sees only encrypted noise, not your file names or the video itself.
    
    
    
    
    
      
    Only who you invite
    
      
    Internet-connected devices join through STUN with an 8-digit code. On your local network, this server is discoverable automatically, but a client still needs the separate short-lived LAN pairing code the first time. Both paths pin device certificates, and trusted LAN clients can be revoked from the Swarm tab.
    
    
    
    
    
      
    What the coordination account actually stores
    
      
    Signing in to generate join codes needs an account (an email address and a password), the same as almost any online service — that account lives on the STUN server, separate from your media server entirely. Your password is one-way hashed, never stored as readable text, and neither is any device's access token. What's stored is the bare minimum to introduce your devices to each other: an email for login, each device's name and a fingerprint of its certificate, and nothing about your library — no file names, folder paths, watch history, or the media itself.
    
    
    
    
    
      
    On your device
    
      
    Your Fire TV's login token and private key are stored using the device's own hardware-backed secure storage (Android Keystore) — not as a plain file anything on the device could just read. If you're on the same home network as your server, your client can even connect directly by local address, skipping the STUN handshake entirely.
